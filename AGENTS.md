# AGENTS.md

Guidance for AI coding agents (and humans) working on this repository. This file holds the rules and the map;
the details are in `docs/agents/`, read on demand.

## What this is

An installable web app that teaches network science in narrated stories, each followed by an explore mode. It
works on desktop, phones and in VR/AR headsets (built for Meta Quest Browser, WebXR). No build step, no
framework, no package.json: plain HTML/JS plus `three.min.js` (three.js r128, vendored, MIT) and `peerjs.min.js`
(PeerJS 1.5.5, vendored, MIT, loaded only for a peer-to-peer room); the studio pastes three.js r128's own loaders
and exporter and meshoptimizer's simplifier (`tools/studio/vendor/`, MIT) into its built file. The app is
deployed by copying the folder to any HTTPS host; VR and installing need HTTPS.

Every story is a package, `packages/<key>/` (`story.json`, `main.js`, its files). What each story shows, its data
and its authors: `docs/agents/stories.md` and `docs/data-and-permissions.md`.

## Layout

The files an agent needs before it knows where to look; every file and folder is in `docs/agents/layout.md`.

- `index.html` - the app shell: shared CSS and DOM and the `HOST` object; owns the single WebGL renderer and any
  XR session, loads and swaps stories.
- `packages/<key>/` - one story each. `main.js` is `HOST.register('<key>', function (HOST) { ... })` returning
  `{ inputs, caption, recenter, panels, xrPose, collab, peek, dispose }`. A built story's sources are
  `packages/<key>/src/` (engine layer, `sets/`, `build.mjs`, a `README.md`, most with a `SPEC.md`, the builder's brief);
  `packages/order.json` (hand-written) is the Stories screen's order; `packages/index.json` is written by
  `node tools/packages/scan.mjs`. Narrations are `packages/<key>/audio/narration.mp3`.
- `stories/list.js` - `STORY_EXTRA` (the studio); `stories/studio.js` and its two parts loaded on demand
  (`studio-convert.js`, `studio-edit.js`) are built from `tools/studio/`.
- `shared.js` - the shared-room client (`HOST.collab`, `HOST.room`) and the headset menu.
- `sw.js` - the service worker (`VERSION`, `SHELL`); `version.json` and `whatsnew/` are written by
  `tools/release.mjs`, `whatsnew.json` by hand at every release.
- `sfx.js` - the shell's sound effects; `occlusion.js`, `ships.js`, `notes.js` - the shell's modules, loaded on
  demand by `HOST.mods` (`index.html`) and run only when they match `MODS_FP`, which `tools/release.mjs` stamps:
  after editing one, run `node tools/release.mjs`; `bodies.js`, `ik.js`, `flight.js`, `output.js` - loaded on
  demand.
- `lowpoly.js` and `packages/<key>/minis.js` - miniatures, generated by `tools/lowpoly/build.mjs`.
- `relay/` - the shared rooms' server (`server.mjs`, Node, no packages), its tests and `README.md`.
- `tools/engine/` - the shared engine parts every built story pastes (`//#use`), and `kit.js`.
- `tools/studio/` - the studio's sources (engine parts, sets, `vendor/` never edited, the build, the converter,
  test scenes, the example scenes' generators); `examples/` - generated example scenes.
- `tools/packages/` - the package contract (`SPEC.md`), `scan.mjs`, `check.mjs`, `publish.mjs`, `template/`.
- `tools/docs/` - `toc.mjs` (the detail files' tables of contents) and `kept.mjs` (proves a restructured doc lost
  no sentence).
- `tools/` - the tests (`smoke.mjs`, `collab.mjs`, `audio.mjs`, `live.mjs`, `update.mjs`, `perf.mjs`),
  `release.mjs`, the voice, notes, trackers and output tools.
- `docs/` - handover pages for people, `history.md` (why rules are as they are) and `docs/agents/`.
  `docs/narration.md` is a generated print-out for people: for one story's words Grep `#<key>` in it.
- `fonts/` - the app's font, B612; no page loads anything from Google.

## The app in brief

- `HOST.start(key)` loads `packages/<key>/main.js` (the studio: `stories/studio.js`), disposes the old story,
  removes every listener it added and runs the new factory; `HOST.swap(key)` does the same in place. A VR/AR
  session survives a change of story: the new story calls `xrAdopt()`.
- A story builds in steps (`LOAD`, `HOST.progress`), tells its chapters in `CH` on story time, follows its
  narration (`NARRATION_SYNC`, `HOST.audio.narration`), and then opens explore mode (`X`, `render*` and `draw*`
  twins).
- Two sets of cards (`HOST.menu`): the main Stories screen and the Experiments set (`story.json`
  `list: "experiments"`). `HOST.stories()` is both; `HOST.list` and Arrange all only the main set. No count of
  stories anywhere a user reads it.
- In a headset each story hangs its Stories screen, panel and scene on one frame, `GL.rig`, set from your head
  or from an anchor (`HOST.anchor`). The shell owns the menu, the subtitles, the settings, sound, occlusion and
  the spaceships.
- In a shared room (`#s=XYZ`) the relay, a peer-to-peer host or this device holds the room's keys: stations
  (`st.<id>`) and room-wide keys (`look`, `lock`, `menus`, `trk`, `name` ...). The shell publishes play, pause,
  jumps, mode changes and `collab.state()`; stories send only effects. In a room a headset's menu is the
  limited one unless the room says full or staff hold both sticks 2 s.
- A change to one package's files alone needs no new `VERSION`: its fingerprint in `packages/index.json`
  reaches devices. A story's author publishes with `node tools/packages/publish.mjs <key> "<what changed>"`
  (`docs/working-on-a-story.md`).
- Releases: bump `VERSION` in `sw.js`, run `node tools/release.mjs`, rewrite `whatsnew.json`. The main site is
  GitHub Pages from `main` (`https://stories.lbi-netmed.com/`); `dev` is the test place on the owner's Coolify
  (`https://stories.lab.lbi-netmed.com/`), and `main` also runs there as the main site's relay. Work goes to
  `dev` first, then `main` once the owner has tried it.
- Left for later (the owner, 23 November 2026): the shared library and rewriting airports, proteins and spatial
  onto the shared engine; (26 November 2026) a headset's Stories screen drawn by the shell with no story loaded
  (`docs/packages-migration.md`, "Left for later").

## Rules every change must keep

The detail files hold the reasons and the exact lines; these are the rules that must never be broken.

### The shell and stories

- Stories create the renderer only with `HOST.makeRenderer(...)`, never `new THREE.WebGLRenderer`.
- Stories never navigate the page. From inside a story switch with `HOST.go(key)` (deferred), not `HOST.start`:
  several handlers run inside the old story's call stack when switching.
- Listeners the shell, `shared.js` or three.js add for themselves (XR sessions, `RTCPeerConnection` and
  `RTCDataChannel`, new audio contexts, `webglcontext*`) are added with `HOST.quiet` set, or a story change
  removes them.
- Every pane exists twice, HTML (`render*`) and canvas (`draw*`): keep both in step.
- A load step never runs long: a headset draws the loading card only between steps. Stories whose sets build
  between frames share one build budget a frame (`BUILD`, `buildTurn`).
- A set's `update` depends only on its params and the time, so seeking works (the live simulations, the flock,
  the robots and the pass story's fish, excepted); step params are never eased.
- Never let the page and its story files come from different versions (a new `index.html` with an old story
  file looks fine but misbehaves); a swap in a headset session waits for a quiet moment; a story needing a
  newer shell is never swapped in.
- `dispose()` clears the story's timers.
- A draw hook (`onBeforeRender`) never calls `getWorldDirection`, `getWorldQuaternion`, `getWorldPosition` or
  `updateWorldMatrix` on the camera it is given: in a headset that is three.js's eye camera, whose pose lives only
  in its matrix, and the call resets the eye to the room's origin (the exposome, v212 to v226). Read
  `camera.matrixWorld` instead.
- Story code never moves `GL.rig` past `HOST.anchor`: check `HOST.anchor.held()` before re-placing and
  `HOST.anchor.locked(kind)` before letting the grip move anything. Moving with the sticks is the shell's:
  stories wait on `xrWalking()`. No story reads A or X (`buttons[4]`): it is the spaceship's boost.
- In a headset no close view brings a `keepClear` set nearer than 0.35 m to the head; the life-size stories
  never move `GL.rig` and the grip moves only their panel (the pass story: the school's holder, `XR.lifeOff`).
- The headset settings (labels, cards, free moving, subtitles, the two sound switches, panels, frame rate,
  refresh rate, automatic quality, occlusion and its smooth edges, moving with the sticks, menu sharing, my
  body, bodies, talk, the menu's level) are the shell's or the device's: never in a story's `state()` or
  `collab.state()`.
- Real-world occlusion never pauses depth sensing in an AR session.
- When a change touches the headset code, apply it to every story: their XR, panel and landing-screen code is
  meant to stay identical apart from story-specific panes (the built stories through `tools/engine/`, the three
  hand-written ones by hand).

### Sound

- Sound belongs to the shell (`HOST.audio`): stories never create or close an `AudioContext`. The one exception
  is the studio's `OfflineAudioContext` in `monoWav` (no output, it plays nothing); keep it the only one.
- Keep both audio engines, the hum and the watchdog. Sound effects play only through `HOST.audio.fx()`.
- Only the flock and the pass story have a background, and `vacuum` is the only continuous sound: never bring
  back hums or other backgrounds unasked (the owner's rule).
- Never put a sound in `collab.state()`. Keep the sound-effect lines (`sfxCue`, `sfxHold`, `sfxAct`,
  `sfxLive`) the same in every story and the studio.
- The studio's emitters follow only the Sound button (this device's mute), never the Sound effects or
  Narration switches.
- After a synthetically narrated story's text changes, run `node tools/voice/narrate.mjs <key>` (not
  `tools/pace.mjs`) and `node tools/voice/check.mjs <key>`.

### Shared rooms

- Bump `FORMAT` in `shared.js` whenever the room's keys or any story's `collab.state()` change shape; a room
  refuses another format.
- `state()` is plain JSON of outcomes only: never the camera, hover, open menus, typed text, timers, page
  layout, anything random or per device (the pass story's language, slideshow, panels mode among them).
- `apply(state())` gives the same `state()` back (echoes are suppressed by value); `apply()` checks every
  field, ignores unknown ones and never publishes.
- A story never publishes anything itself except effects; effects are ephemeral (`e.<station>`) and their data
  means the same on every device.
- Keep the shared hooks identical in every story and the studio (the `collab` object, the ray and press lines,
  the grip line, `xrRoomOnly`, `xrAway`, `xrCards`, `xrAllHere`, `xrWalking`, `xrIdle`, Recenter, `caption`,
  `panels`); a story's hooks must stay in step with its pointer code.
- Every write of a move by hand carries `ts` (and `h: 1` while held); every comparison of such a value leaves
  `ts` and `h` out; `setView(v, now)` keeps the same lines in every story.
- The relay's password never goes into a log line, link, address, room key or file; it is kept per relay
  origin in `localStorage` `relayTokens`.
- Tests never use PeerJS's public server: peer to peer is tested only through the relay's own `/peerjs`.

### Releases and files

- Bump `VERSION` in `sw.js` whenever an app file outside a package changes, or installed copies (and headsets)
  keep serving the old cache. Then run `node tools/release.mjs` (it writes `version.json`, stamps the shell's
  release into `index.html` and writes `sw.js`'s story entries; commit them; `--check` says whether they are
  current) and rewrite `whatsnew.json` by hand for the release (`version`, `date`, a handful of short sentences
  each under `new`, `test`, `untested`); `--check` fails while it names another release.
- A new file the app needs goes into `sw.js` `SHELL` and into `relay/server.mjs` `APP_FILES` or `APP_DIRS`
  (a package's files are its own); `node relay/test.mjs` checks every file `SHELL` names.
- Keep `README.txt` (user-facing notes) in sync with structural changes; chapter timings are also in
  `docs/narration-timings.txt`.
- A new page in `STORY_EXTRA` needs its icon in `tools/lowpoly/shell.js`.
- Windows: `.gitattributes` checks every text file out with LF, since the builds' `--check` compare bytes. A
  tool finds its own folder with `fileURLToPath(import.meta.url)`, never `new URL(import.meta.url).pathname`.

### Science and wording

- Never show patient or variant data (the muscle story: nothing about zebrafish either); no GTEx ids, donor
  details or images, no poster pictures (figures are redrawn in 3D).
- The tissue topology, soil and CDK5 stories compute nothing scientific in the app: they look numbers up
  (`TDATA`, `SDATA`, `CDATA`; CDK5's layouts, colours and links are the authors', never laid out again).
- Soil: never call a link an interaction or a hub a keystone, never say the wheat changes the microbiome or
  that the line changes nothing; keep the hedges and the illustrative labels.
- Mutation: the coupling is our stand-in and says so; never call the circuit better or more accurate; the
  poster's numbers only as "in the authors' test". Qubits: example networks only, computed live by `QMATH`; the
  real run's numbers only as "in the real network".
- The qubits and aging ovary stories use American spelling; every other story British. The pass story is in
  English and German, every string in both; its language is per device; never change
  `packages/airports/main.js` or `packages/spatial/main.js` for its sake.
- No 2D charts as chapters (the owner's rule); the ovary story draws no trend, comparison or score charts. In
  the ovary story one model fades out before the next comes in, and a set writes no depth while it fades
  (`fadeDepth`).

### The studio

- At a station the scene's frame is the room's: moving or turning a studio circle never moves the scene.
- Motions, paths, behaviours and trackers draw through the pose pipeline; an item's record never changes while
  it moves.
- Nothing see-through while editing: every editing look is opaque lines, small opaque meshes and opaque tags.
- Trigger cubes are each person's own unless `all: true`; what they reveal is never in `state()` or sent. The
  one exception (the owner, 16 November 2026): only for a cube opted in to send (its record has `send`
  entries), the fact that a person walked into it or out of it goes to the room as the ephemeral effect `send`
  from that person's device; what the cube shows, hides, changes or starts for them stays their own. Pointing
  at an item whose press has `hover`/`unhover` sends is sent likewise; nothing else of pointing is.
- A sequence's play state (`qr.<id>`), a press stamp (`pr.<id>`) and a screen's `play` are never in
  `layout.json` or Undo.
- Locked items refuse every move, size and delete; a copy is never locked; the room's records and Undo are
  never refused.
- Editing, Upload and conversion are never offered with `&visit`. Convert to GLB and adding textures are page
  only (a headset says *Convert on a laptop*), except the saves of Fewer triangles and Change texture.

### Reporting

- Report anything only a device can show (controllers, placement, comfort, shared spaces, calibration, anchors,
  trackers, sound zones, occlusion, ships, the studio's grips, sticks and emitters, frame rate) as untested
  until tried there, and how sounds and voices sound as unheard.

## Conventions

- Match the surrounding style: 2-space indent, single quotes, semicolons, compact one-line helpers, short
  comments that say why. No frameworks or bundlers; do not add dependencies. External scripts: none beyond the
  vendored ones.
- Writing in the UI is plain British English, short sentences, no jargon without a gloss (the two American
  stories and the pass story's German excepted). Numbers shown in a story are computed from the data at load
  time, not hard-coded, wherever possible.
- A story's speech sounds like a human scientist speaking to a general audience (the owner, 23 November 2026):
  one speaker, "we" and "you", short spoken sentences, one running image, round numbers, no headings or small
  print read out. The voice has its own words (`data-say` on a line; the headset's subtitles show them); the
  panel keeps the key points and the exact numbers (`tools/voice/README.md`, "The script").
- Scientific content is illustrative but must be correct: only add interactions and locations that are well
  documented (complexes, textbook pathways, Human Protein Atlas / UniProt locations). Say "in this map" for
  statistics computed on the curated sets.
- Avoid 2D graphs (bar charts, line charts, scatter plots, matrices, survival curves): in AR and VR they are
  dull, and a poster shows them better. A quick graph in passing is fine; a whole chapter needs something that
  uses the space (the owner's rule, October 2026).

## Testing

There is no unit-test suite. What each block protects is `docs/agents/testing.md`; `--list` on `smoke.mjs`,
`collab.mjs` and `audio.mjs` names the checks without running them.

**When the suites run** (the owner, 7 November 2026: "only running when pushing to main makes sense for now"):
every suite a change touches runs before `main` moves, the smoke test always. A push to `dev` gets only the
cheap checks: `node --check` on the changed files, the builds' `--check`, `node tools/packages/scan.mjs --check`
and `node tools/release.mjs --check`; a red result there is not chased. Running is free (CPU); chasing red
results costs tokens, and most were the tests' own or the machine's. A builder may run its own block or round
once (`--only`).

- Serve the folder (`python3 -m http.server 8123`), then `node tools/smoke.mjs http://127.0.0.1:8123/`.
  Playwright with Chromium is needed; WebGL runs in software headlessly, so frame rates are low. A 404 for a
  missing narration MP3 is expected; any other console error fails it.
- Every test page sets `collabAutoAll`, `collabAutoWelcome` and `tutorialHold` to `off`, `collabAskDefault` to
  `walk` and `collabMenus` to `full` unless its round asks otherwise: keep that when adding a round.
- `tools/perf.mjs` is a measuring tool, not a test; it reads `FPS_FAKE` and `OCCL_FAKE` out of
  `tools/smoke.mjs`, so do not rename them.

| Touched | Run before `main` moves |
| --- | --- |
| anything | `node tools/smoke.mjs <url>` |
| sound | `node tools/audio.mjs <url>` |

## Working economically (token budget)

- **Match the model to the job.** The strongest model only to build hard things and to integrate. Critiques,
  verification, screenshot sweeps, audits, data extraction and mechanical edits go to a cheaper model at lower
  effort.
- **One review round.** One critique and one fix per piece of work; a second round only for major findings.
  Verify findings in one batched pass per area, and only the high-severity ones.
- **Cap the visual checks.** Small screenshots (640x400), contact sheets, about 20 images per agent, and
  numbers instead of pictures where possible.
- **Give each agent only what it needs.** Its own section of a spec; text descriptions of images; line ranges
  of the big files, never whole files.
- **Set a budget and plan the run.** Say roughly what a multi-agent run will cost before starting one. A
  workflow runs at most (CPUs - 2) agents at once; keep headless-browser work to a few agents at a time.
  Hitting the usage limit mid-run kills in-flight agents, so have agents write their notes as they go.
- **Prefer cheap tests.** The smoke block and the set harness catch most problems; a builder runs them once at
  the end, not after every step.
- **Show every screenshot.** Agents keep screenshots in one folder outside the repository; the conversation
  that runs them posts each new picture to the chat.
- **Keep sources small and in the repository.** Edit `src/` sources, not built files; keep generators and
  manifests so nothing has to be rediscovered.

Why (numbers in `docs/history.md`): building the tour spent three quarters of its tokens on critiques, fix
rounds and verification; from v91 to v122 the full suites caught about 5 real bugs against about 70 failures
that were the tests' own or the machine's.
