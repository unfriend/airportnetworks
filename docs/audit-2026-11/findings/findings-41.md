### Background build jobs produce the measured heap per frame (nmd heart, ovary section stains)   [perf-frame]  gain: high  risk: low  sure: plausible
Where: packages/nmd/src/sets/motor.js:721-822 (polygonise), 848-860 (coronaries), 882-891 (heartStep), 1090, 1211 (idle); tools/engine/e2_scene.js:57 (buildTurn), 223 (updateSets~3); ovary section.js:707, 813 via look.js:83-151
What: While the motor set is hidden, buildTurn calls motor.idle() every frame (2-8 ms on desktop, 1 ms in XR) until the heart is built. nmd has no `early()` step, so the heart is built only after load. Its inner loop allocates for every surface vertex: p0, heartVertex's `cand` of about 20 [d, q] pairs plus col, wt and the return array (L694-714), grad() and v3 arrays (L790-796), and an `act` object with BODY.filter for every block (L743). Ovary's section stains follow the same pattern (idle, plus K.showMs(dt, 4) in update) through look.js builder.
Change: Build the heart during the load steps, as ovary did for its organ in v136 (add motor.early, call it from nmd's init), or after the first frames with a cap. Make the job allocate nothing per vertex: scratch arrays for cand, col and grad, and typed arrays sized from a first count. Have perf.mjs call `finish()` on these sets before it measures (sweep.mjs already does), so the chapters get measured and not the build.
